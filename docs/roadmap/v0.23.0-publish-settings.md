## 1. 目标与现状

补上发布配置的写入，使输出目录、图集、压缩和代码生成配置可由已授权任务自动完成。

当前证据：`src/fairygui_agent/mcp_server.py:1041` 仅提供 get_publish_settings，publish 读取现有配置执行，尚无配置 setter。

## 2. 本版本范围

- 全局和包级输出路径、文件格式、图集与压缩策略及已有原生分支覆盖。
- 代码生成开关、输出目录、命名规则等原生配置。
- 配置修改预览、保存与文件回读；配置写入与执行发布分开。

## 3. 接口草案

| 接口 | 输入、作用域与用途 |
|---|---|
| `fgui_preview_publish_settings` | settings + 全局/包选择器；返回变化文件、输出路径和覆盖来源 |
| `fgui_set_publish_settings` | 结构化补丁，明确 scope 和 save 语义 |
| `fgui_get_publish_settings / fgui_publish（既有）` | 保留读取和发布执行入口，返回配置来源与实际输出 |

MCP 使用 snake_case，Bridge Action/参数沿用既有 camelCase 约定；最终签名以实施时确认的原生能力和兼容性为准。读取应返回足够的当前值、作用域与限制，使调用方能先读后写。

## 4. 关键语义与边界

- 区分全局值、包覆盖和继承；清除覆盖必须恢复继承，不能写一个当前解析后的全局值冒充继承。
- 路径规范化并报告最终绝对输出位置；目录修改不隐式发布、创建业务生成文件或删除旧产物。
- 配置保存可能影响 project/package settings，必须核实实际保存范围；不顺带保存用户脏组件。
- 二进制/XML、压缩及代码生成改变会影响消费者兼容性，预览列出变化；不把发布成功当作 Unity 已验收。
- 这是工程/包设置操作，不混入单文档 apply_batch；若另设配置计划，必须有独立快照和能力标记。

## 6. 验证与验收

| 场景 | 必须证明的结果 |
|---|---|
| 全局与包覆盖 | 修改只作用于选定 scope，清除覆盖正确恢复继承 |
| 路径与格式预览 | 预览位置与实际发布位置一致，写配置时不发布 |
| 图集/压缩策略 | 配置保存重载与实际原生产物相符 |
| 代码生成开关和命名 | 只在显式发布时产生预期代码文件 |
| 用户脏文档 | 保存配置不顺带保存或丢弃文档内容 |
| 非法组合与保存失败 | 写前拒绝或报告实际 settings 保存状态 |

- [ ] 上述场景的自动化/宿主契约检查通过，未知字段和越权目标不能静默接受。
- [ ] 已在专用隔离 Editor 工程执行实际原生写入、保存和重载回读；涉及视觉/发布的场景另给对应证据。
