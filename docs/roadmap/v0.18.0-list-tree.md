## 1. 目标与现状

完成常规列表剩余编辑字段，并支持可持久化的树列表结构与预置项层级。

规划时的缺口是列表高级字段及预置项 level 写入；现已扩展现有四个列表工具，保留原有调用方式，协议仍为 `2.0`，MCP 工具数仍为 110。

## 2. 本版本范围

- 列表选择控制器绑定、不可见项折叠、点击滚入视野等原生设置。
- 树模式、缩进及点击展开相关配置，限定为 Editor 可持久化字段。
- 在既有最终有序 items 协议中增加 level，并处理树的父子顺序。

## 3. 已交付接口

| 接口 | 输入、作用域与用途 |
|---|---|
| `fgui_get/set_list_settings（扩展）` | 增加高级设置与树模式字段 |
| `fgui_get/set_list_item_resources（扩展）` | items 支持显式 level；继续使用 sourceIndex 保留原项 |
| 既有接口的 `tree` 回读 | settings 返回结构摘要，items 返回 parentIndex/isFolder 节点；无需新增读取工具 |

MCP 使用 snake_case，Bridge Action/参数沿用既有 camelCase 约定；最终字段与能力标记已按原生持久化验证。读取应返回足够的当前值、作用域与限制，使调用方能先读后写。

## 4. 关键语义与边界

- sourceIndex 始终引用调用前清单，不随重排改变；省略属性仍保留，包括内部控制器/文本/图标覆盖。
- 树项顺序采用前序；首项从根层开始，不允许跳过尚不存在的父层；文件夹标志若为原生必需字段，先核实再定 schema。
- 选择控制器与分页控制器是不同绑定，不能互相覆盖；空绑定明确解除。
- 树模式开关、默认展开状态和仅设计态预览状态必须区分；不把运行时展开当作发布默认值。
- 切换树/普通列表时对层级的保留或拒绝规则必须明确；不能静默丢弃 items 或覆盖值。

## 8. 实施与验收记录（2026-10-21）

- 既有 settings 接口增加 `selectionController`、`foldInvisibleItems`、`scrollItemToViewOnClick`、`treeViewEnabled`、`indent`、`clickToExpand`。选择控制器按当前组件作用域解析，空串解绑，与分页控制器互不覆盖。
- 既有 items 接口支持 `level`（整数 0..255），按前序检验首层和父层连续性。文件夹由后续层级推导，不开放原生未持久化的 `isFolder` / `expanded`。`sourceIndex` 仍引用调用前项，复制时保留省略的文本、图标和控制器覆盖。
- 树转普通列表前必须显式将层级全部设为 0，避免原生保存静默丢失层级。普通模式不持久化 indent/clickToExpand，接口拒绝在该模式写这些字段，回读通过 `inactiveTreeFields` 说明。
- 增加 `list_settings_advanced`、`list_item_levels` 能力标记；新字段在直接调用和批量入队前均检查旧插件能力。复用原有 revision、operation_key、回执与单次保存机制。
- 完整自动化测试 128 项通过，其中新增 6 项 Python 测试及其覆盖的 16 个编译插件宿主场景；包括非法类型/层级/索引、不变性、旧插件拒绝、批量、保存失败和原生部分变更检测。
- 通过真实 MCP 与专用 Editor 6.1.4 完成 38 项检查：高级字段保存重载、两类控制器独立、多层项增删重排与覆盖保留、无效输入不污染旧数据、模式切换、批量别名、发布层级和 clearOnPublish 组合。三张状态截图已人工核对缩进、层级与重排结果。
- 原生临时探针另行证明：文件夹预览折叠后保存，XML 和预置数据不变；重载恢复默认展开。接口只声明 `nativeDefaultFolderExpanded=true`、`expandedStateFieldAvailable=false`。预置项内部名为 expanded 的控制器覆盖独立保留，不把它宣称为 Editor 节点默认展开字段。
- 已核对发布时清空示例项只影响导出，源项及覆盖保留；关闭清空后重新发布恢复示例项。未执行 Unity/设备业务运行时验证，也不生成 itemRenderer/itemProvider。
- 可复用测试源码和夹具入库；临时探针、隔离工程、日志、截图、发布及安装暂存均在仓库外。不以离线 XML 编辑替代 MCP 接口验收。
