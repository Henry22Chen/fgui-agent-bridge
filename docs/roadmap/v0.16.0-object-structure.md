## 1. 目标与现状

支持复制已配置好的对象/对象组，以及可靠调整绘制层级，避免重复搭建和逐字段重建。

当前证据：`plugin/main.ts:3864` 仅创建原生节点；现有插入/删除、分组接口不提供对象克隆或已有子对象顺序调整。

## 2. 本版本范围

- 同一活动文档中复制一个或多个直属对象，可指定偏移和名称冲突策略。
- 读取完整子对象顺序，按最终有序 ID 清单重排，支持置顶/置底的明确结果。
- 克隆时保留实例属性、样式、Gear、Relation 和分组，并返回旧 ID 到新 ID 的映射。

## 3. 接口草案

| 接口 | 输入、作用域与用途 |
|---|---|
| `fgui_duplicate_objects` | targets + offset + naming_policy；返回 created 与 id_map |
| `fgui_get_child_order` | 读取当前根组件的完整显示顺序 |
| `fgui_reorder_objects` | ordered_ids 完整替换显示顺序，默认不保存 |

MCP 使用 snake_case，Bridge Action/参数沿用既有 camelCase 约定；最终签名以实施时确认的原生能力和兼容性为准。读取应返回足够的当前值、作用域与限制，使调用方能先读后写。

## 4. 关键语义与边界

- 只复制当前根下的对象；ID 由 Editor 分配，不能手工拼接或依赖下标定位。
- 复制集合内的 Relation、分组引用重映射到克隆对象；指向集合外的引用按明确策略保留或拒绝，默认不能静默断开。
- 复制组件实例只复制父文档配置，不复制或修改共享组件定义；根遮罩引用默认仍指向原对象。
- 根控制器和文档级 Transition 不随对象隐式复制；其既有引用保持，影响必须回传。
- 完整重排清单必须覆盖当前全部直属对象，拒绝重复、遗漏、外来 ID；组成员关系和显示层级是两个独立概念。
- 优先使用可验证的原生复制机制；如涉及系统剪贴板，必须确认并保护用户剪贴板，不能无提示覆盖。

| 场景 | 必须证明的结果 |
|---|---|
| 单对象与多对象复制 | 新 ID 唯一，属性和资源引用保留，返回映射可用于后续调用 |
| 组与内部 Relation | 克隆内部引用指向新对象，外部引用遵循声明策略 |
| 带 Gear 和实例覆盖的对象 | 配置保存重载一致，共享资源未变 |
