## 1. 目标与现状

补齐控制器重命名/删除、页面删除/重排和首页配置，并以引用检查避免破坏 Gear、按钮和实例覆盖。

当前证据：`plugin/main.ts:852` 的 controller properties 仅含 exported/alias；现有页面工具只有追加、重命名和切页，没有删除、重排及 homePage 写入。

## 2. 本版本范围

- 控制器重命名/删除、页面删除/重排、homePage/homePageType 和自动单选层级设置。
- 联动顺序编辑和已验证的跟随页面特殊目标值；保留既有显式 pageId 协议。
- 建立可复用的只读引用扫描，覆盖当前文档及项目内相关组件实例的控制器/页面引用。

## 3. 接口草案

| 接口 | 输入、作用域与用途 |
|---|---|
| `fgui_rename/remove_controller` | 先返回引用影响预览，显式选择拒绝或受限清理策略 |
| `fgui_remove/reorder_controller_pages` | 稳定页面 ID；顺序使用最终 ID 清单 |
| `fgui_set_controller_properties（扩展）` | 首页规则与 autoRadioGroupDepth，不混同当前选中页 |
| `fgui_reorder_controller_actions / 既有 Action 扩展` | 调整执行顺序；跟随规则使用类型化参数 |

MCP 使用 snake_case，Bridge Action/参数沿用既有 camelCase 约定；最终签名以实施时确认的原生能力和兼容性为准。读取应返回足够的当前值、作用域与限制，使调用方能先读后写。

## 4. 关键语义与边界

- 页面删除和重命名不能重建剩余页面 ID；清单重排不改变 ID 与页面对应关系。
- 引用扫描包括 Gear、按钮/列表/滚动绑定、联动条件/目标、首页和导出控制器实例覆盖；未知引用不能当作无引用。
- 默认拒绝删除仍被使用的对象；显式清理只在已验证影响范围内执行，不能用 force 忽略未知引用。
- 需要改其他活动/脏文档或无法安全更新的外部实例时返回受影响文档清单并拒绝写入；跨文档执行由 v0.25.0 接续。
- 切页只改变当前状态；首页配置必须单独保存并通过重新打开/发布后的默认行为核对。
- 联动特殊值采用有名模式，不向调用方暴露未解释的魔法字符串；循环检查仍然有效。
