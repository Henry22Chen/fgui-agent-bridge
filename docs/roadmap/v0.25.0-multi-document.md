- 状态：待安排，尚未实现。
- 优先级：P2。
- 编写日期：2026-10-21；能力基线为 v0.13.0 / `99c9edc` / Editor 6.1.4。

## 1. 目标与现状

让一个已授权 UI 任务可以可靠串行处理多个组件文档，并明确每个文档的执行、保存和失败结果。

当前证据：`plugin/main.ts:4410` 的 applyBatch 只绑定一个活动文档；现有外部编辑交接已存在，但没有跨文档计划，也缺少显式打开/关闭/重载完成状态闭环。

## 2. 本版本范围

- 显式文档打开、关闭、重载和就绪状态，保持用户未保存内容的归属边界。
- 跨多个文档的有序计划、每文档 revision、跨文档有作用域的结果引用和单一总回执。
- 失败后停止、按文档报告前缀结果，以及基于快照检查的续执行判断。

## 3. 接口草案

| 接口 | 输入、作用域与用途 |
|---|---|
| `fgui_get_document_state / fgui_close_document / fgui_reload_document` | 明确 loading/ready/dirty/closed，不把调用返回视为完成加载 |
| `fgui_plan/apply_multi_document` | project + documents + 每文档 revision + operation_key + 白名单操作 |
| `fgui_get_multi_document_result` | 返回每个文档及保存阶段状态，unknown 不能作为安全重放依据 |

MCP 使用 snake_case，Bridge Action/参数沿用既有 camelCase 约定；最终签名以实施时确认的原生能力和兼容性为准。读取应返回足够的当前值、作用域与限制，使调用方能先读后写。

## 4. 关键语义与边界

- 只处理一个明确 FairyGUI 项目和已确认 Editor 实例，不按窗口标题切项目，也不承诺自动热重载插件或重连 MCP 传输。
- 执行前核对所有文档快照，执行每个文档前再核对；发现用户脏文档或来源不明变更时不得自动保存/放弃。
- 明确 save_policy（例如每文档完成后保存）；即使最后才保存也不是多文件原子提交，失败必须逐文档列出 saved/persisted。
- 跨文档引用带文档命名空间，禁止把不同文档相同对象 ID 当作同一目标。
- 沿用受控 Action，不提供任意脚本透传；包级文件移动、导入、发布等独立操作不混进文档批量。
- 本版本不自动回滚已完成文档；续执行必须核对日志与当前状态，跨进程恢复和事务撤销归 v0.26.0。

## 6. 验证与验收

| 场景 | 必须证明的结果 |
|---|---|
| 多组件顺序编辑 | 每个文档 revision、目标和保存结果准确，不串文档 |
| 重复计划和超时 | 同键不重复执行，查询可定位已完成前缀 |
| 中间文档失败 | 后续不执行，已完成文档状态与持久化结果真实 |
| 用户脏文档/并发修改 | 预检或执行前停止，不自动保存或丢弃 |
| 关闭/重载后读取 | 等到 ready 后重新取对象，避免使用失效引用 |
| 跨文档同名/同 ID | 命名空间明确，不误写同名对象 |

- [ ] 上述场景的自动化/宿主契约检查通过，未知字段和越权目标不能静默接受。
- [ ] 已在专用隔离 Editor 工程执行实际原生写入、保存和重载回读；涉及视觉/发布的场景另给对应证据。
