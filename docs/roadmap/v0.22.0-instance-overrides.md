## 1. 目标与现状

能清除单个实例覆盖并正确恢复继承，同时为组件资源替换提供可预检的覆盖迁移策略。

当前证据：现有实例 setter 不接受 null；`ApplyCustomProperty(null)` 会移除 XML 覆盖但不恢复当前显示。`plugin/main.ts:4123` 的资源替换使用原生语义，只返回前后覆盖清单。

## 2. 本版本范围

- 按内部路径/属性 ID 清除文本、图标或导出控制器覆盖，并核对当前 effective 值。
- 组件替换增加保持原生、保留兼容覆盖、显式映射等可区分策略。
- 预览可迁移、不可迁移、冲突和即将丢失的覆盖，不能默认静默丢弃。

## 3. 接口草案

| 接口 | 输入、作用域与用途 |
|---|---|
| `fgui_clear_component_instance_override` | target + 属性/控制器选择器；恢复继承并返回 effective 值 |
| `fgui_plan_component_replacement` | 只读分析目标定义及覆盖迁移，返回映射和冲突 |
| `fgui_replace_object_resource（扩展）` | 显式 migration_policy / override_map；默认仍为既有原生行为 |

MCP 使用 snake_case，Bridge Action/参数沿用既有 camelCase 约定；最终签名以实施时确认的原生能力和兼容性为准。读取应返回足够的当前值、作用域与限制，使调用方能先读后写。

## 4. 关键语义与边界

- 空字符串仍表示显式覆盖为空；清除覆盖使用独立操作，不能改变现有 value 参数语义。
- 清除控制器覆盖要区分源组件默认页、父控制器/Gear 当前影响和持久化状态；不能仅把 XML 字段设为 null。
- 必要时重建/刷新单个原生实例，但必须保持外层 ID、几何、层级、Gear、Relation、分组及其他覆盖；不能 discard 整个脏文档。
- 迁移在修改前核实目标路径、导出属性、控制器和页面 ID；名称相同不代表页面/属性兼容。
- 不兼容覆盖的丢弃必须是明确策略并列出清单；没有策略时拒绝。旧调用默认行为保持兼容。

## 6. 验证与验收

| 场景 | 必须证明的结果 |
|---|---|
| 文本/图标恢复继承 | XML override 消失，当前显示与重载结果均恢复源值 |
| 空字符串覆盖 | 仍可保持为空，不被误判为继承 |
| 控制器清除 | 源首页规则与有效页解释正确，父级联动影响可诊断 |
| 兼容及显式映射迁移 | 新路径/页面有效，其他实例与源资源未改变 |
| 不兼容项/旧计划 | 冲突写前拒绝，源定义变化使预检失效 |
| 脏文档中局部操作 | 仅处理本任务实例，不丢弃用户其他修改 |
