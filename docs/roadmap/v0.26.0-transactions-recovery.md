## 1. 目标与现状

在已验证的对象/文档操作范围内提供完整结构快照、可检查的撤销/重做和受控失败恢复，补齐无人值守任务的恢复能力。

当前证据：现有多数结构修改返回 agentUndoSupported=false；单文档/多文档批量失败保留已执行前缀。属性栈不能恢复删除对象、控制器或资源结构。

## 2. 本版本范围

- 为明确白名单中的对象创建/删除/复制/重排、分组、Gear/控制器和实例覆盖操作建立前后快照。
- 结构事务撤销/重做、事务状态查询、失败后在快照未发生外部变化时的显式恢复策略。
- 本地持久化日志与中断后的只读恢复分析；跨进程恢复必须核实文件和文档状态。

## 3. 接口草案

| 接口 | 输入、作用域与用途 |
|---|---|
| `fgui_apply_batch / apply_multi_document（受控扩展）` | 显式 transaction / failure_policy，不改变旧调用默认保留前缀行为 |
| `fgui_get_transaction / fgui_plan_recovery` | 读取快照覆盖范围、状态、冲突和可恢复性 |
| `fgui_undo/redo_transaction / fgui_apply_recovery` | 仅在当前内容符合记录的前/后态时恢复，返回逐文档结果 |

MCP 使用 snake_case，Bridge Action/参数沿用既有 camelCase 约定；最终签名以实施时确认的原生能力和兼容性为准。读取应返回足够的当前值、作用域与限制，使调用方能先读后写。

## 4. 关键语义与边界

- 先声明 can_undo、恢复范围和不支持操作；包资源导入/删除、发布产物和外部文件不因文档事务而变得可撤销。
- 事务恢复使用完整原生结构并保留稳定对象/页面 ID、显示顺序、Gear、Relation、分组、实例覆盖和默认省略语义；只恢复受支持的设计态。
- 撤销前核对当前内容等于事务后态，重做前核对等于前态；存在用户修改、未知 dirty 或并发文件变化时返回 conflicted，不能强制覆盖。
- 失败自动恢复是显式策略，例如 rollback_if_unchanged；恢复本身失败时返回 partially_restored 和逐文档差异，不能宣称全部回滚。
- 区分原先未保存的内存态和磁盘态，不能用恢复一次交易顺带落盘用户原有未保存修改。
- 崩溃/断连后的 unknown 不触发盲重放；日志和快照仅在项目本地运行目录保存，校验完整性且不纳入 Git。
- 播放中的 Transition、MovieClip 或游戏副作用不属于完整回滚保证；恢复后必须重新定位对象并回读。

## 6. 验证与验收

| 场景 | 必须证明的结果 |
|---|---|
| 结构创建/删除/复制撤销重做 | ID、顺序、引用和内容恢复，原始未保存状态不被错误保存 |
| 控制器/Gear/实例事务 | 页面 ID、绑定与覆盖恢复，未知节点不丢失 |
| 用户修改后的撤销请求 | 返回 conflicted，用户内容保持 |
| 中途失败与受控恢复 | 支持范围内恢复可核对；不支持操作写前拒绝 |
| 恢复阶段自身失败 | 报告 partially_restored、逐文件/文档状态和剩余差异 |
| 进程中断与日志损坏 | 先分析不盲重放，损坏快照明确失败 |
| 保存/重载与设计态恢复 | 完整 XML 和设计态可验证，不承诺运行时副作用回滚 |
