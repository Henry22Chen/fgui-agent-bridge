# 批量编辑与集中验收方案

本方案针对真实会话中每次 MCP 调用约 3–4 秒的调用端固定开销、大量小操作、长上下文和布局返工。Bridge 无法控制调用端调度或模型容量，因此交付重点是减少跨 MCP 调用次数、缩小返回量并明确 Editor/XML 交接。

## 交付及接口

| 能力 | 实现约定 | 验收 |
|---|---|---|
| `fgui_apply_batch` | 一个文档、一条队列请求，最多 200 个白名单操作；Editor 分配创建 ID，`ref`/`$ref` 引用；revision 防止陈旧计划覆盖；默认不保存、摘要返回 | 20 个对象各改 4 个属性，从 80 次队列请求降到 1 次；SDK 契约和真实 Editor 回读 |
| `fgui_get_batch_result` | 操作键与参数绑定，按进程保存 running/succeeded/failed 回执；相同提交不重复执行 | 超时后可查；键复用不同参数拒绝；失败报告已完成项，绝不伪称原子回滚 |
| `fgui_get_objects` | 一次按目标/字段读取，返回文档 revision；验证可不返回整树 | 摘要响应显著小于全树；ID/根/直属作用域检查 |
| `fgui_capture_states` | 预检查所有页面，串行切页/截图，finally 恢复指定控制器；返回带标签联系图及元数据 | 多状态只需一次队列请求，失败也恢复；不能把图片生成等同视觉通过 |
| `fgui_begin_external_edit` / `fgui_finish_external_edit` | 起点必须干净；令牌绑定原生文档实例与完整编辑态快照；外部写入后验证内存未变再重载，不写用户 XML | 错工程、错文档、陌生修改、令牌复用拒绝；正常 XML 改动重载后可回读 |
| `fgui_diagnostics` | 仅本地读取有界计时记录；记录 readiness、请求往返、Editor 执行及队列等待 | 超时也有记录；明确不包含调用端/模型耗时 |
| 素材检查脚本/技能 | PNG 尺寸及 alpha 可见边界；先按设计稿确定坐标、字体和缩放，集中修改与比较 | 透明留白明确；不自动修图或修改业务逻辑 |

## 语义和边界

- 原有工程目录、PID、原生 exe 和启动时间检查不变，协议仍为 2.0，功能版本升至 0.10.0。
- 批量白名单禁止导入、发布、保存所有文档、任意脚本或切换工程/文档。单步 save 禁止，只允许整批结束后显式保存当前组件。
- dry_run 检查结构、作用域和引用；动态原生约束仍在执行时校验。批量并非完整原子事务：失败立即停止，不自动保存，不重复创建，不自动丢弃修改。
- 回执绑定 Editor 进程实例；Editor 重启后不能把旧 unknown 当成安全重试依据。失败或 running 状态先查询实际结果。
- 创建组件资源仍使用原生组件创建入口；批量创建的是当前组件内控件。ID 由 Editor 生成，不让模型猜编号。
- XML 交接不是 XML 写入器。外部脚本只在明确授权范围写入，重载前再次核对内存快照；不自动保存、发布或关闭业务工程。
- 联系图恢复指定根控制器，不承诺恢复运行预览中的业务副作用；仅支持普通设计编辑态。截图后仍需实际观察。
- 保持既有 Skill 章节结构；细节集中在能力参考，计划示例单独按需读取。

## 实施与验证

1. 独立新分支/worktree 实现插件、MCP、CLI 和文档，保持运行中的共享安装不变。
2. 编译 TypeScript，执行 Python 回归与原生边界宿主测试。
3. 在专用隔离 FairyGUI 工程验证批量创建/回读/保存、重复提交、状态截图恢复、外部编辑交接和性能计数。
4. 给出请求次数、返回字节及实际计时。真实 Editor 无法验证的项目如实列出，不修改生产工程作为替代。
